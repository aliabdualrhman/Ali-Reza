# دليل التجهيز — من صفر إلى تطبيق يعمل

جهازك حالياً عليه `git` و `python` فقط. هذا الدليل يوصلك لبيئة تطوير كاملة.
نفّذ الأقسام بالترتيب — كل قسم يعتمد على ما قبله.

---

## القسم ٠ — توجيه التخزين بعيداً عن قرص C:

**نفّذ هذا القسم قبل أي تثبيت.** قرص `C:` عندك فيه ١٥ جيجا حرة فقط،
وبيئة أندرويد الكاملة تحتاج ٣٠-٤٠ جيجا.

المشكلة ليست في مكان التثبيت وحده: الأدوات تكتب مخابئها (caches) داخل
مجلد المستخدم على `C:` حتى لو ثبّتها على قرص آخر. مخبأ Gradle وحده
يتجاوز ٥ جيجا، ومخبأ حزم Dart يتراكم مع الوقت.

### ٠.١ إنشاء مجلدات العمل على I:

```bash
mkdir I:\dev\android-sdk I:\dev\gradle I:\dev\pub-cache
```

### ٠.٢ ضبط متغيرات البيئة

نفّذ كل أمر في نافذة أوامر، ثم **أغلق النافذة وافتح واحدة جديدة**
حتى تُقرأ القيم الجديدة:

```bash
setx ANDROID_HOME "I:\dev\android-sdk"
```

```bash
setx GRADLE_USER_HOME "I:\dev\gradle"
```

```bash
setx PUB_CACHE "I:\dev\pub-cache"
```

```bash
setx ANDROID_USER_HOME "I:\dev\android-home"
```

> `setx` تكتب القيمة بشكل دائم في حساب المستخدم. لا تستخدم `set`
> فهي تعيش في النافذة الحالية فقط وتضيع عند إغلاقها.

### ٠.٢.١ نقل مخابئ Android Studio (يوفّر ٢-٤ جيجا على C:)

Android Studio يكتب إعداداته وفهارسه في `C:\Users\<اسمك>\AppData`
بغضّ النظر عن مكان تثبيته. الفهارس وحدها تصل ٣ جيجا لمشروع متوسط.

لنقلها، أنشئ ملفاً باسم `idea.properties` داخل مجلد تثبيت
Android Studio في المسار `bin\idea.properties`، وضع فيه:

```
idea.config.path=I:/dev/studio/config
idea.system.path=I:/dev/studio/system
idea.plugins.path=I:/dev/studio/plugins
idea.log.path=I:/dev/studio/log
```

> **انتبه لاتجاه الشرطة:** هذا الملف يستخدم `/` لا `\` حتى على ويندوز.
> الشرطة العكسية فيه تُقرأ كرمز هروب ويفشل المسار بصمت.

نفّذ هذه الخطوة **بعد تثبيت Android Studio وقبل أول تشغيل له** —
لو شغّلته أولاً سينشئ المجلدات على C: وتحتاج نقلها يدوياً.

### ٠.٣ ماذا يُثبَّت وأين

| الأداة | المكان | الحجم التقريبي |
|---|---|---|
| Flutter SDK | `I:\dev\flutter` | ٣ جيجا |
| Android Studio | `I:\dev\android-studio` | ٤ جيجا |
| Android SDK | `I:\dev\android-sdk` | ١٠ جيجا |
| مخبأ Gradle | `I:\dev\gradle` | ٣-٥ جيجا |
| مخبأ Dart | `I:\dev\pub-cache` | ١-٢ جيجا |
| مخابئ Android Studio | `I:\dev\studio` | ٢-٤ جيجا |

المجموع نحو ٢٥ جيجا، كلها على `I:` الذي فيه ٣٠٥ جيجا حرة.

**ماذا يبقى على `C:` رغم ذلك؟** نحو ١-٣ جيجا: ملفات التثبيت المسجّلة في
النظام، ومجلد `.android` الصغير، وملفات مؤقتة تُنظَّف بعد التثبيت.
هذا مقبول تماماً مع ١٥ جيجا حرة.

> **ملاحظة عن الأداء:** قرصا الجهاز كلاهما SSD، و `I:` على قرص فيزيائي
> منفصل عن قرص النظام. هذا ترتيب **أفضل** من التطوير على `C:` — عمليات
> البناء الثقيلة لا تتزاحم مع ويندوز على نفس القرص.

### ٠.٤ تخطَّ المحاكي — استخدم هاتفاً حقيقياً

محاكي أندرويد يضيف ٨-١٢ جيجا لكل نسخة نظام، لكن السبب الأهم لتجنّبه
هنا ليس المساحة: **تطبيقنا يقوم على الموقع والحركة**. المحاكي يعطي
موقعاً ثابتاً مزيّفاً، فلا تستطيع اختبار تتبع سائق يتحرك فعلاً، ولا
دقة GPS في شوارع بغداد، ولا سلوك التطبيق حين تضعف الشبكة.

استخدم هاتف أندرويد حقيقي عبر كبل USB. تحتاج:

1. تفعيل `خيارات المطوّر`: `الإعدادات → حول الهاتف` ثم اضغط
   `رقم الإصدار` سبع مرات متتالية.
2. من `خيارات المطوّر` فعّل `تصحيح أخطاء USB`.
3. وصّل الهاتف واقبل رسالة `السماح بتصحيح الأخطاء` التي تظهر عليه.

للتحقق:

```bash
flutter devices
```

## القسم ١ — أدوات التطوير الأساسية

### ١.١ تثبيت Flutter SDK

Flutter هو الإطار الذي سنبني به التطبيقين. يأتي مع لغة Dart بداخله.

1. نزّل حزمة Flutter لويندوز من: https://docs.flutter.dev/get-started/install/windows
2. فك الضغط إلى `I:\dev\flutter` — **لا تضعه في `Program Files`**، المسار الذي يحوي
   مسافة أو يحتاج صلاحيات مدير يكسر أدوات Flutter.
3. أضف `I:\dev\flutter\bin` إلى متغير البيئة `Path`:

```bash
setx PATH "%PATH%;I:\dev\flutter\bin"
```

4. أغلق النافذة وافتح واحدة جديدة، ثم تحقق:

```bash
flutter --version
```

### ١.٢ تثبيت Android Studio

نحتاجه لثلاثة أشياء: حزمة تطوير أندرويد (SDK)، والمحاكي، وأدوات التوقيع.

نزّله من https://developer.android.com/studio وثبّته بالإعدادات الافتراضية.
عند أول تشغيل سيطلب تنزيل مكوّنات إضافية — وافق عليها كلها.

ثم من داخله: `Settings → Plugins` وثبّت إضافتَي **Flutter** و **Dart**.

### ١.٣ قبول تراخيص أندرويد

خطوة يتعثر فيها الجميع. بدونها لن يُبنى التطبيق:

```bash
flutter doctor --android-licenses
```

اضغط `y` لكل ترخيص يظهر.

### ١.٣.١ تثبيت cmdline-tools — الخطوة التي يتعثر فيها الجميع

معالج Android Studio **لا يثبّت هذه الحزمة**، وبدونها لا تُقبل تراخيص
أندرويد ولا يُبنى أي تطبيق.

جرّب أولاً من داخل Android Studio:
`SDK Manager` ← تبويب `SDK Tools` ← أشّر على
`Android SDK Command-line Tools (latest)` ← `Apply`.

> انتبه: الضغط على **اسم** الحزمة يحدّدها فقط ولا يؤشّرها. لا بد من الضغط
> على المربع الصغير نفسه حتى تظهر علامة ✓، وعندها يصير زر `Apply` فعّالاً.

**إن فشل التحميل** (وهو شائع مع الاتصالات غير المستقرة)، نزّل الأرشيف
مباشرة من https://developer.android.com/studio#command-line-tools-only
وتحقق من بصمة SHA-256 المعروضة بجانبه، ثم فُكّ **محتوى** المجلد
`cmdline-tools` الذي بداخله إلى:

```
I:\devndroid-sdk\cmdline-tools\latest```

> **مصيدة المسار:** انسخ *محتوى* `cmdline-tools` لا المجلد نفسه. لو نسخت
> المجلد لصار المسار `cmdline-tools\latest\cmdline-toolsin` ولن يعثر
> عليه Flutter. الصحيح أن يكون `sdkmanager.bat` في
> `cmdline-tools\latestin\` مباشرة.

### ١.٤ الفحص الشامل

```bash
flutter doctor -v
```

يجب أن ترى ✓ أمام: Flutter، Android toolchain، Android Studio.

**علامة ✗ أمام "Visual Studio" أو "Chrome" لا تهمّنا** — هذه لتطبيقات
ويندوز والويب، ونحن نبني للجوال.

### ١.٥ تثبيت Node.js

نحتاجه لأداة Supabase ولوحة التحكم الإدارية لاحقاً.
نزّل نسخة LTS من https://nodejs.org ثم تحقق:

```bash
node --version
```

## القسم ٢ — تجهيز الباك إند (Supabase)

### ٢.١ إنشاء المشروع

1. سجّل في https://supabase.com (الخطة المجانية تكفي تماماً للتطوير).
2. `New Project` — اختر اسماً، وكلمة مرور قوية لقاعدة البيانات
   (**احفظها في مدير كلمات المرور، لن تُعرض ثانية**).
3. المنطقة: اختر `Frankfurt (eu-central-1)` — أقرب مركز بيانات للعراق،
   وفرق زمن الاستجابة عن المناطق الأمريكية محسوس في التتبع اللحظي.

### ٢.٢ تفعيل PostGIS

من لوحة Supabase: `Database → Extensions` وابحث عن `postgis` وفعّله.
(ملف الترحيل `0001` يحاول تفعيله أيضاً، لكن التفعيل من اللوحة أضمن.)

### ٢.٣ تطبيق ملفات الترحيل

الطريقة الأسهل للمبتدئ — عبر محرر SQL في اللوحة:

1. افتح `SQL Editor` في لوحة Supabase.
2. افتح ملفات `backend/supabase/migrations/` **بالترتيب الرقمي**
   (`0001` ثم `0002` ... حتى `0008`).
3. الصق محتوى كل ملف ونفّذه، وتأكد من نجاحه قبل الانتقال للتالي.

> **الترتيب إلزامي.** كل ملف يعتمد على الجداول والأنواع التي أنشأها سابقه.

الطريقة الاحترافية (بعد تثبيت Node) — عبر أداة Supabase:

```bash
npm install -g supabase
```

```bash
supabase link --project-ref <معرّف-مشروعك>
```

```bash
supabase db push
```

### ٢.٤ نسخ مفاتيح الاتصال

من `Settings → API` انسخ:

- **Project URL** — عنوان مشروعك
- **anon public key** — المفتاح العام، يوضع داخل التطبيق

> **مهم:** لا تضع `service_role key` في التطبيق إطلاقاً. هذا المفتاح
> يتجاوز كل سياسات الأمان (RLS) ومن يحصل عليه يملك قاعدة بياناتك كاملة.
> مكانه الوحيد هو الخادم أو Edge Functions.

### ٢.٥ ضبط تسجيل الدخول بالهاتف

من `Authentication → Providers → Phone`:

- فعّل `Enable Phone provider`
- اختر مزوّد الرسائل. Twilio هو الافتراضي لكنه **مكلف للأرقام العراقية**
  وقد ترفض بعض الشبكات رسائله.

> **تنبيه للسوق العراقي:** موثوقية رسائل SMS من المزوّدين العالميين
> لشبكات آسياسيل وزين والكورك متفاوتة. قبل الإطلاق اختبر التوصيل فعلياً
> على الشبكات الثلاث، وخطّط للتعاقد مع بوابة SMS محلية.
> أثناء التطوير استخدم أرقام الاختبار (القسم ٢.٦) لتتجنب الكلفة.

### ٢.٥.١ واتساب بدل الرسائل النصية

واتساب أوسع انتشاراً في العراق من SMS وتوصيله أوثق. Supabase يدعمه كقناة
لرمز التحقق، لكن **حصراً عبر مزوّد Twilio أو Twilio Verify**.

التغيير في كود التطبيق سطر واحد:

```dart
await supabase.auth.signInWithOtp(phone: phone, channel: OtpChannel.whatsapp);
```

**الشرط الذي يؤخّرك:** منذ مارس ٢٠٢٤ لم تعد Twilio توفّر رقم واتساب جاهزاً
— يجب أن تملك **حساب WhatsApp Business برقمك الخاص**، وهو يتطلب توثيق
نشاط تجاري لدى Meta بوثائق تسجيل شركة رسمية.

خلاصتها: **واتساب يحتاج شركة مسجّلة أولاً.**

### ٢.٥.٢ الخيارات المجانية

#### تسجيل الدخول بحساب جوجل — الأقوى مجاناً

**مجاني بلا سقف.** وكل مستخدم أندرويد يملك حساب جوجل أصلاً (شرط لتحميل
التطبيقات من Play Store)، فالدخول بضغطة واحدة بلا انتظار رمز ولا كلفة.

**لكن انتبه لفرق جوهري:** جوجل تثبت *هوية* المستخدم، لا *رقم هاتفه*.
ومشروعنا يحتاج الرقم كوظيفة لا كتوثيق — السائق يجب أن يتصل بالراكب
حين لا يجده.

الحل: الدخول بجوجل (مجاني)، ثم طلب الرقم عند **أول طلب رحلة** لا عند
التسجيل. فتدفع رمز تحقق واحداً لكل مستخدم يطلب رحلة فعلاً، بدل كل من
حمّل التطبيق وتصفّحه ثم اختفى.

#### الدخول بالبريد الإلكتروني — مجاني لكنه لا يناسبنا

Supabase يرسل رموز البريد مجاناً (بحدود منخفضة على الطبقة المجانية،
وتحتاج خادم بريد خاصاً مثل Resend للإنتاج).

المشكلة ليست تقنية: **السائقون في العراق لا يستخدمون البريد الإلكتروني
عملياً.** ستخسر نصفهم عند أول شاشة. صالح كخيار إضافي، لا كأساسي.

#### التصفح بلا حساب

Supabase يدعم الحسابات المجهولة. دع الراكب يفتح التطبيق ويشوف الخريطة
والأسعار قبل أن يُطلب منه أي تسجيل — يرفع نسبة إكمال التسجيل كثيراً.
مجاني تماماً.

#### بوابة SMS ذاتية (هاتف قديم + شريحة محلية)

طريقة عملية منتشرة في المنطقة: هاتف أندرويد قديم بشريحة عراقية وباقة
رسائل، يعمل كبوابة إرسال. الكلفة تقارب الصفر بعد ثمن الباقة.

**عيوبها حقيقية:** شركات الاتصال تحظر الإرسال الجماعي من الأرقام
الشخصية، والسرعة محدودة، وتعتمد على جهاز يجب أن يبقى شغّالاً ومتصلاً.
مقبولة لعشرات الرسائل يومياً في مرحلة التجربة، لا للإنتاج.

#### الخطة الموصى بها

| المرحلة | القناة | الكلفة |
|---|---|---|
| التطوير | أرقام اختبار Supabase | صفر |
| التجربة الأولى | **دخول بجوجل** + رقم عند أول رحلة | شبه صفر |
| الإنتاج | جوجل + واتساب + SMS احتياطي | منخفضة |

> **احتفظ بأكثر من قناة دائماً.** لو فشلت واحدة — غيّر المستخدم جهازه،
> أو رقمه غير مسجّل بواتساب — يحتاج مساراً بديلاً وإلا خسرته عند أول شاشة.

### ٢.٦ أرقام اختبار بلا رسائل

من `Authentication → Providers → Phone → Test OTP` أضف:

| الرقم | الرمز |
|---|---|
| `+9647701111111` | `111111` |
| `+9647702222222` | `222222` |

الأول للراكب والثاني للسائق أثناء التطوير.

## القسم ٣ — مفاتيح خرائط جوجل

نحتاج مفتاحاً واحداً لكل منصة (أندرويد و iOS).

1. https://console.cloud.google.com → أنشئ مشروعاً جديداً.
2. `APIs & Services → Library` وفعّل هذه الخدمات:
   - **Maps SDK for Android**
   - **Maps SDK for iOS**
   - **Directions API** — لحساب المسار والمسافة والزمن
   - **Places API** — للبحث عن العناوين
   - **Geocoding API** — لتحويل الإحداثيات إلى عنوان مقروء
3. `Credentials → Create Credentials → API Key`.
4. **قيّد المفتاح فوراً** — `Restrict Key` وحدّد التطبيقات والخدمات المسموحة.
   المفتاح غير المقيَّد يمكن لأي شخص استخدامه على حسابك.

> **الفوترة:** جوجل تطلب بطاقة ائتمان حتى للاستخدام ضمن الحد المجاني.
> ضع تنبيه ميزانية (`Billing → Budgets & alerts`) بمبلغ صغير من اليوم الأول —
> استدعاء Directions API في حلقة خاطئة يستهلك مئات الدولارات بسرعة.

## ملاحظة عن iOS

بناء تطبيق iOS **يتطلب جهاز Mac** — هذا قيد من آبل لا يمكن تجاوزه،
ويحتاج أيضاً اشتراك مطوّر بـ ٩٩ دولاراً سنوياً للنشر.

كود Flutter الذي نكتبه يعمل على المنصتين، لكن خطوة البناء والنشر
لـ iOS تحتاج Mac. الخيارات:

1. جهاز Mac (حتى Mac Mini مستعمل يكفي)
2. خدمة بناء سحابية مثل Codemagic أو GitHub Actions مع مُشغّل macOS
3. **الأنسب لك الآن:** ابدأ بأندرويد وحده. حصة أندرويد في السوق العراقي
   تتجاوز ٩٠٪، وتأجيل iOS لا يعطّل الإطلاق.
